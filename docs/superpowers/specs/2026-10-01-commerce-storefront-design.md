# 桌面商品展厅与购物助手设计

日期：2026-10-01。状态：已确认方向，待用户审阅本设计文件。

## 目标与已确认约束

用户需要展示已导入商品的前端，采用「商品展示区 + 聊天框」，视觉具有质感，交互有优雅的动画。技术方向已确认 React + TypeScript + Vite。沿用此前桌面端、免登录演示、会话记录可隐藏的要求。

聊天是购物需求的唯一输入入口：不增加独立搜索框、预算表单或类目筛选器。点击商品仅用于查看详情、把商品引用带入聊天；加购和交接继续经过现有提案与确认流程。商品区用于浏览真实商品和展示对话候选。

首版成功标准：打开页面即能看到数据库商品图片和价格；可分页浏览、查看详情、持续聊天与恢复会话；聊天返回的真实候选能同步到商品区；动画不中断输入、滚动、焦点或交易确认。

## 当前代码与数据基础

- `demo/commerce.html`、`demo/commerce.js`、`demo/commerce.css` 是原生聊天演示页。
- `api/commerce_demo.py` 在显式非生产配置下挂载演示入口、静态资源与独立访客身份。
- `/api/v1/catalog/products` 提供 active 商品的稳定游标分页；摘要尚无图片、价格和库存。
- 商品详情提供媒体与 SKU；报价接口提供价格、可用量及可购买原因。
- 已核对演示数据库包含 100,000 件 Amazon 商品。99,996 件有图片 URL；图片二进制未下载，链接可用性未逐一验证。
- 价格、默认 SKU 和库存为明确标记的模拟测试数据；商品原始文本主要为英文。库存未知是预设场景。
- 现有本地演示的自由文本能力有边界。页面重构不能作为真实 LLM 已接入或理解能力已完善的证据。

## 技术选择与取舍

前端放在独立的 `frontend/` 目录。使用 React、TypeScript、Vite、React Router、TanStack Query、CSS Modules 和 CSS 变量。交互动画以 CSS transition 为基础，复杂的组件进入退出和布局过渡使用 Motion 的 React API；实际依赖版本在实施时核对官方兼容要求并固定 lockfile。

React 适合商品网格、详情、会话与购物状态的组件化维护；TypeScript 约束 API DTO；TanStack Query 管理请求取消、分页和缓存。暂不引入 Redux，展示状态由组件和小范围 context 管理，服务端数据仍由请求缓存管理。

相比继续原生 JS，本方案增加构建和依赖管理，但降低复杂 UI 的状态维护成本。相比 Next.js，本方案复用现有 FastAPI，减少服务端渲染与缓存的运行边界；代价是首版不提供 SSR 和搜索引擎优化。当前用途是本地数据展示与 Agent 测试，SSR 收益较低。CSS Modules 比现成商城主题更容易控制图片比例、留白和层级，代价是需要自行维护视觉规范。

开发环境由 Vite 代理现有 API、认证与访客入口至 HTTPS 后端，浏览器保持单一 origin，明确验证 Cookie、来源校验与 CSRF。构建后由 FastAPI 同源提供静态文件，无需常驻 Node 服务。沿用 `/demo/commerce`；资源放在独立前缀，不能遮蔽 API、访客及 handoff 路由。SPA fallback 仅覆盖前端页面路径。

## 页面与视觉规范

定位为安静、清晰的精品生活方式商店。主要识别来自真实商品图片的统一展示尺度，以及右侧始终可用的购物助手。避免促销信息堆叠、红色价格轰炸、装饰渐变和大面积阴影。

| 角色 | 值 |
| --- | --- |
| 背景 | `#FAFAF8` |
| 图片底板 | `#F0F1EE` |
| 正文 | `#252923` |
| 次要文字 | `#747A71` |
| 主操作与选中 | `#385447` |
| 分隔线 | `#E2E5DE` |

字体栈使用 `Helvetica Neue`、`PingFang SC`、系统无衬线字体，不依赖在线字体。正文 14–16px，页面标题 28–36px；名称和价格左对齐，价格不超过商品名称的视觉层级。弱化卡片边框，按钮、图片区域和详情面板使用不同尺度的圆角，避免所有元素套同一种卡片。

顶部约 64px，只保留品牌、会话记录、购物袋入口。内容区商品与聊天约 70:30；聊天宽度约 360–420px，商品网格根据剩余宽度在 2–4 列间调整。目标验收尺寸为 1280×800、1440×960 和 1920×1080。首版不设计移动端；较窄桌面可以收起聊天区并通过明显入口恢复。

商品卡片使用 4:5 图片区域，`object-fit: contain` 保留完整商品。下方展示名称、品牌（有才展示）、人民币报价及必要库存提示。英文名称最多两行，详情页显示完整可用标题。页面以简短标题和实际商品开场，不加入占据首屏的大型营销横幅。

## 展示与聊天联动

初始展示真实目录的第一页，每页 24 件，使用明确的「加载更多」按钮。首页顺序沿用稳定游标排序，不把默认顺序称为个性化推荐。无总数量接口时，不编造结果总数。

新对话默认回到目录；聊天返回候选后展示候选商品，标题改为「为你挑选」。候选视图提供「浏览全部商品」返回目录。仅澄清、确认或回答而没有新候选时，保留已有商品，不能突然清空。推荐依据只取服务端实际返回内容，不添加虚构文案。

点击卡片打开商品详情：图片、名称、来源属性、SKU、报价和库存。详情可选「向助手询问这件商品」，把经验证的商品 ID 引用加入聊天输入，用户可以补充文字后发送；不自动提交加购。详情开启时聊天上下文保留。

购物袋展示服务端购物车，并复用现有确认与模拟交接流程。商品区报价为展示时读取的快照，不能直接用其授权交易。写操作仍由服务端重新校验权限、价格、库存和版本。

会话记录从顶部开启一个可关闭面板，沿用按用户隔离的本地历史与服务端归属验证。切换历史恢复聊天、已展示候选和待确认动作；新会话、刷新和重试不得复用其他会话的结果。

## 商品卡片数据接口

新增只读展示接口，建议 `GET /api/v1/storefront/products?limit=24&cursor=...`，返回 `items` 和 `next_cursor`。新增 `POST /api/v1/storefront/products/resolve` 接收至多 100 个去重后的商品 ID，用于解析聊天候选；这是只读批量解析，不执行交易。两个接口共享应用层拼装逻辑。

每项包含商品 ID、名称、品牌、类目引用、首图 URL、展示 SKU ID、价格（币种、整数分、版本、读取时间）、可购买状态与原因。库存未知、缺价、缺图均显式表达；保留原目录端点的契约。

首版展示 SKU 确定规则：在 active SKU 中按 `sku_code`、ID 选择第一项，详情页允许查看实际规格；不将所选报价宣称为最低价。不存在 active SKU 时返回不可购买和空报价。来源模拟标记用于页面统一的「演示商品，价格与库存为模拟数据」提示。

目录分页由 catalog 服务负责；媒体和 SKU 使用批量读，价格和库存通过各自领域服务增加必要的批量读能力。禁止逐商品 HTTP 请求或每张卡片一次 SQL 的 N+1 方案。只读解析过滤未上架商品并返回缺失 ID，前端保留其余有效结果。

查询正确性通过代表性分页、候选解析和 SQL 次数验证；数据量 100,000 件时不在浏览器下载完整目录。现有文本检索的多语言语义能力不属于本次改造范围。

## 动画规范

动画要表现操作结果与空间关系，不承担装饰作用。默认缓动 `cubic-bezier(0.22, 1, 0.36, 1)`；收起可使用稍快的 ease-in。优先使用 transform 和 opacity，避免每帧修改网格宽度或大量触发布局。

| 交互 | 效果 | 时长 |
| --- | --- | --- |
| 按钮按下 | 极小位移或缩放，颜色反馈 | 100–140ms |
| 商品悬停 | 图片轻微放大至 1.025，名称强调 | 180–220ms |
| 聊天栏展开/收起 | 面板平移与透明度变化，主区在终态完成布局调整 | 220–280ms |
| 商品详情开启/关闭 | 遮罩淡入，详情面板短距离平移 | 220–280ms |
| 对话更新商品 | 保留旧结果至新结果就绪，再交叉淡入；仅新出现卡片做短距离进入 | 180–240ms |
| 加载更多 | 新增商品轻淡入，不移动已有卡片 | 160–200ms |
| 会话面板 | 短距离平移与透明度变化 | 180–220ms |
| 消息到达 | 小幅透明度变化，不逐字伪装流式回复 | 120–180ms |

商品进入效果仅作用于可见的新卡片，最多错开 4 项、总延迟不超过 100ms；不为长列表所有节点添加动画。快速连续开关可以中断并平滑转向，不能排队播放。退出动画期间禁止透明但仍可点击的遮挡层。

图片加载保持固定尺寸，通过渐显替换占位，失败显示稳定占位与「暂无图片」，不反复自动重试。加载状态采用静态骨架和清楚的等待提示，避免持续闪光。

尊重 `prefers-reduced-motion`：取消平移、缩放、错开和布局动画，保留即时切换或不超过 80ms 的淡入。动画不自动抢走焦点，不强制滚动正在阅读的用户；消息区仅在用户接近底部时跟随，否则提示有新消息。

## 身份、错误与可靠性

继续复用独立访客、HttpOnly Cookie、内存访问令牌、来源校验和 CSRF。生产环境不因前端升级开放访客绕过。用户文本与商品字符串通过 React 文本渲染；富文本如有需要必须显式净化，禁止直接插入不可信 HTML。构建资源遵守现有 CSP，外链图片使用 HTTPS、懒加载和 `referrerPolicy=no-referrer`。

请求失败区分目录、报价、图片和对话故障。目录失败保留已有结果并提供重试；价格或库存服务不可用时显示「暂时无法获取」，不得用缓存或随机数字冒充当前报价。聊天重试沿用原 turn ID；交易重试沿用原幂等键。用户主动取消、新会话或历史切换后，旧请求结果不能覆盖当前页面。

详情面板支持 Escape、焦点约束和关闭后焦点恢复；会话开关提供展开状态；图像有商品名称 alt；输入法确认不会触发发送；等待和错误使用适度的可访问提示。

## 验证与交付

后端测试覆盖批量拼装、稳定分页、候选顺序、未上架过滤、SKU 选择、模拟标记、缺图/缺价/未知库存和依赖错误，检查请求数不随商品数线性增长。保持已有身份、购物确认和幂等回归测试。

前端使用 Vitest 与 Testing Library 验证会话隔离、过期结果、请求重试、候选联动和输入法行为；使用独立 Playwright 浏览器验收真实数据首屏、分页、详情、聊天、会话恢复、购物确认、断网和 reduced-motion。构建与类型检查必须通过。

视觉验收保存上述桌面尺寸截图，检查图片比例、英文长标题、无图商品、聊天长消息与抽屉遮挡；动画验收通过浏览器实际交互，检查连续开关、滚动中更新、键盘焦点和减少动画模式。真实 LLM 缺失时分别记录页面链路通过与自由文本能力未验证，不能用假响应宣称 Agent 已完善。

交付包括前端源码与 lockfile、批量展示 API、同源构建挂载、相关测试和中文运行说明。下载文件、导入断点、环境秘密及现有无关修改不纳入前端交付。

## 首版范围与剩余风险

首版不新增支付、订单履约、商家管理、移动端、多语言翻译、语义检索或图片镜像服务。外链图片可能失效、原始商品描述不统一、模拟价格不代表市场价格；视觉质量通过合理的图片容器和失败处理改善，不能把不完整源数据包装成真实商业承诺。

主要新增成本是 Node 构建依赖、批量展示读接口及动画回归。采用独立前端目录、复用领域服务与同源部署控制维护边界；如未来转向公开商城，再单独评估 SSR、SEO、图片代理与缓存策略。
