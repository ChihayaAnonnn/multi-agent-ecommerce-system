# 桌面聊天演示

本页用于本地试用购物 Agent：打开后直接聊天，左侧查看或切换会话记录，可以收起侧栏。购物需求、商品比较、加购提案和确认均通过同一个聊天框输入。界面仅面向桌面，未提供移动端布局。

当前本机地址：<https://localhost:18443/demo/commerce>。

## 视觉与交互

主区白色 `#FFFFFF`，侧栏及输入框浅灰 `#F6F7F9`，正文深灰 `#202124`，辅助文字灰色 `#667085`，结构边框 `#E4E7EC`，键盘焦点蓝色 `#3056D3`。中文使用苹方及系统中文字体，正文 16px、初始标题 30px。

侧栏宽 260px，对话正文与输入框最大宽 760px。初始输入框居中，开始对话后移到底部；消息区独立滚动。用户消息显示为浅灰气泡，助手答复直接排在白色主区。商品和比较表格是答复的一部分，不再拆成操作面板。

相较于复刻完整 ChatGPT 界面，本页仅保留购物对话需要的会话记录、输入和发送，不添加模型菜单、附件、语音、快捷提示卡。视觉层次由留白和字号建立，不使用渐变、装饰卡片或大面积阴影。

动画仅用于侧栏收起/展开（180ms）和请求等待提示。不逐字模拟回复，不加入消息飞入效果；尊重 `prefers-reduced-motion`。输入框支持 Enter 发送、Shift+Enter 换行，中文输入法候选确认不会触发发送。按钮和输入框提供可见键盘焦点。

## 跳过登录如何实现

`POST /demo/commerce/guest` 仅随显式开启的非生产演示页挂载。它通过现有演示注册和登录服务自动建立随机独立账号，复用来源校验、限流、密码哈希、访问令牌和 Secure HttpOnly 刷新 Cookie。随机密码不返回给浏览器。

页面启动时优先通过已有 Cookie 恢复身份；只有收到 401 才创建访客。网络故障、依赖故障和来源校验失败不会悄悄切换到新身份。生产环境不会挂载该入口，原购物 API 仍要求真实 Bearer 主体并校验资源归属。

这样可以复用现有购物车、会话和确认实现，避免共享演示账号串车，也避免给所有购物接口增加匿名绕过。代价是访客仍受现有身份服务和注册限流约束；Cookie 清除或到期后会创建新访客。

相关配置：`ECOM_COMMERCE_DEMO_ENABLED=true`、`ECOM_IDENTITY_DEMO_MODE=true`，以及明确的 `demo` / `development` / `test` 身份环境；身份密钥、来源白名单和 HTTPS 仍需按现有认证模块配置。

## 会话记录与恢复

- 浏览器 `localStorage` 按服务端返回的 `user_id` 分区保存会话标题、会话 ID、用户文本、结构化答复和失败请求。最多保存 50 段对话，每段保留最近 100 条消息。
- 访问令牌和 CSRF 值只在页面内存中保存，刷新令牌只在 HttpOnly Cookie 中保存。
- 打开历史对话先查询服务端，确认归属和有效期，再恢复界面。过期对话可以阅读，继续购物需新建对话；默认购物会话有效期为 24 小时。
- 恢复对话时重建已展示商品及当前待确认动作，取消和成功确认会清除待确认状态。实际执行时由服务端再次核验提案、价格、库存和权限。
- 页面关闭或网络中断后，原消息保留重试入口，沿用原 `turn_id`、请求内容与确认幂等键，避免重复提交购物操作。

选择浏览器记录而非新增服务端消息表，是因为现有服务端保存购物状态和轮次响应，但不保存原始用户消息；本次局部界面改版可直接复用它的身份与会话授权。代价是历史记录不跨设备同步，清除浏览器站点数据会丢失界面记录。后续如需跨设备同步，应单独设计服务端消息持久化。

## 现有 Agent 能力边界

界面支持将“比较第1款和第2款”“加入第1款”等明确指向已展示商品的输入转换成现有 API 的商品 ID，所有 ID 仍由服务端验证。加购默认先提出 1 件的确认摘要，输入“确认加购”才执行。

当前本机验收实例未注入真实 LLM，自由文本可能只得到澄清问题。聊天页面不会扩展 Agent 的自然语言理解能力，也不会把正在下载的商品数据自动导入目录。完善 Agent 和数据导入是后续工作。

## 验证记录（2026-09-30）

- 全套 Python 测试：167 项通过。使用本次运行新建的隔离 MySQL 库和空闲 Redis DB；验证后清理所拥有的临时库。既有测试库迁移记录与表结构不一致，本次未修复或清空它。
- JavaScriptCore 契约检查：10 组通过，覆盖并发刷新、过期响应隔离、自然文本输入、凭据不持久化、待确认状态恢复、已展示商品引用、会话归属检查与原请求重试。
- 独立无头 Chrome（1440×960）：免登录入口、侧栏收起、消息发送、刷新恢复、历史切换、新对话、断网重试通过，没有页面 JavaScript 错误。使用独立临时浏览器配置，未操作用户已有浏览器会话。
- 商品操作验收先用明确的目录条件获取服务端真实候选，再通过页面输入“加入第1款”“确认加购”，验证提案、刷新恢复与购物车提交。此步骤验证界面与购物服务接通，不代表自由文本选品能力已完成。
